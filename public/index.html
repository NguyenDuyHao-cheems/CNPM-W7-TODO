Thông tin kiến trúc Version 4: P2P Direct Collaboration (WebRTC DataChannel)
NFR: High Availability khi server trung tâm gặp sự cố; hòa giải xung đột bằng Lamport Logical Timestamp (LWW)
Kiến trúc N-Layer + P2P Khi server hoạt động: Client–Server → SQLite3 → SSE Broadcast. Khi server sập: WebRTC DataChannel truyền gói tin JSON trực tiếp giữa 2 trình duyệt không qua server trung gian.
Đồng bộ P2P khi mất Server (V4) Sử dụng WebRTC RTCDataChannel (kênh taskflow-p2p). Tái sử dụng Granular Event Protocol từ V3.5 (task_created, task_updated, task_deleted).
Hòa giải dữ liệu (Conflict Resolution) Áp dụng Last-Write-Wins (LWW) kết hợp Lamport Logical Timestamp: Mỗi mutation mang lamport_ts và peer_id; bản ghi có timestamp cao hơn sẽ thắng khi xảy ra xung đột đồng thời.
Phương thức Signaling Hỗ trợ 2 chế độ: 1-Click Local Tab Sync (qua BroadcastChannel giữa 2 tab thử nghiệm) và Manual SDP Exchange (sao chép chuỗi mã hóa qua LAN không cần bất kỳ server nào).

Cấu hình kết nối P2P (WebRTC DataChannel)

Giao tiếp trực tiếp giữa 2 thiết bị khi server trung tâm mất kết nối

Sử dụng kênh phát sóng cục bộ (BroadcastChannel) để tự động trao đổi thông điệp WebRTC Offer/Answer trong vài mili-giây mà không cần copy paste thủ công!

Trạng thái P2P: Sẵn sàng kết nối

1. Dành cho Máy A (Khởi tạo Offer)

3. Dán mã Trả lời từ Máy B (Answer)

2. Dành cho Máy B (Nhận Offer & Trả lời)

💡 Sau khi P2P kết nối thành công, bạn có thể tắt hẳn server backend (Ctrl+C hoặc pkill -f server). Hai máy vẫn tạo và chuyển trạng thái task trực tiếp cho nhau bình thường!
